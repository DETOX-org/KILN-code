# Contributing to DETOX Code

Thank you for your interest in contributing to **DETOX Code**! We welcome contributions from developers, designers, writers, and community members of all skill levels.

---

## Early Stage Notice

DETOX Code is currently in its **early concept and architecture setup stage**. 

At this phase, the most impactful contributions include:
- Reviewing and refining architectural proposals (`docs/architecture/`)
- Participating in technology stack and design discussions
- Proposing feature concepts and problem evaluation mechanisms
- Helping establish repository standards, CI validation, and documentation

Please note: **Implementation of product microservices/modules (frontend, backend, judge) will commence once initial architecture RFCs and technology stack decisions are finalized.**

---

## How Can I Contribute?

### 1. Reporting Bugs
If you find a bug or error in repository configuration or documentation:
1. Search existing [GitHub Issues](https://github.com/DETOX-org/Detox-Code/issues) to verify it hasn't already been reported.
2. If it hasn't, submit a new issue using the **Bug Report** template.
3. Provide a clear title, detailed description, and steps to reproduce.

### 2. Suggesting Features & Enhancements
Feature proposals are encouraged!
1. Check existing issues to see if your idea is already under discussion.
2. Open a new issue using the **Feature Request** template.
3. Explain the problem your feature solves, the proposed solution, and alternative approaches considered.

### 3. Submitting Pull Requests (PRs)
1. **Fork/Branch**: Create a descriptive topic branch from `main`:
   - `docs/add-architecture-rfc`
   - `feature/issue-template-update`
   - `fix/typo-in-readme`
2. **Focus**: Keep Pull Requests focused on a single logical change. Large, monolithic PRs are harder to review.
3. **Style & Formatting**: Follow formatting rules in `.editorconfig`.
4. **Commit Messages**: Use clear, structured commit messages (e.g., `docs: update roadmap phase 1`, `fix: correct markdown lint error`).
5. **Submit**: Create your Pull Request against the `main` branch using the **Pull Request Template**.

---

## Coding and Style Guidelines

- **File Formatting**: Ensure all files strictly adhere to the rules in `.editorconfig` (UTF-8, LF line endings, trailing whitespace trimmed).
- **Documentation**: Keep documentation clear, concise, and formatted in GitHub Flavored Markdown.
- **Dependencies**: Do not introduce new third-party dependencies or framework configurations without an approved architectural issue or RFC.
